# Spec: 多 Agent 群聊模式（ChatSession）

## Problem Statement

当前「标准模式」的讨论本质是「并行产出 + 汇总」，不是真正的讨论：

- 各 Agent 独立生成初始提案，然后各自回应、最后由合成者汇总，彼此之间没有交锋、追问、让步的过程；不同角色设定（冲突制造者 / 情感锚点 / 意外推手 / 世界守护者）的优势体现不出来，讨论结果趋于平庸。
- 作者被隔离在流程之外：只能在审查点追加指令，不能实时参与、引导、打断讨论。
- 前端体验是管线式的（提案 → 审查 → 合成 → 审查 → 应用），不是对话；讨论过程不可见，执行中容易「卡住」，作者不知道 Agent 正在做什么。
- 后端基于轮询的异步任务 + 内存会话，缺少实时推送；上下文是简单全量拼贴，讨论稍长就会膨胀、失真、超出预算。

## Solution

改为「群聊模式」：一个类似微信群的实时讨论房间，多个 Agent 角色与作者作为群成员自由发言，讨论达到共识后由合成者产出最终方案，作者可随时手动终止。标准模式整体移除。

核心机制：

- **发言权调度（意愿度制）**：任一时刻至多一个成员发言，其余等待；系统对每个 Agent 动态计算「意愿度」，选出最高者发言，兼顾话题相关性与公平性，防止垄断或冷场。
- **作者参与**：作者是群成员，可随时插入发言（实时并行，不阻塞当前 Agent 生成）；支持 @ 某角色 定向召唤（强意愿加成），可点击群成员快速 @。
- **共识检测（综合检测）**：关键词信号 + 观点收敛（向量聚类）+ Agent 自评三路信号并判定，达成后由合成者产出总结，讨论结束。
- **上下文管理（分层摘要）**：L1（最近 5 条完整消息）+ L2（最近 20 条滚动摘要）+ L3（全讨论要点），控制 token 预算并让每个 Agent 聚焦。
- **实时推送（SSE）**：消息、当前发言人、Agent 思考/生成状态、共识进度实时推送到前端。
- **本地语义检索**：`@xenova/transformers` 本地 Embedding（多语言 MiniLM，384 维）+ Qdrant 向量库（Docker 部署），用于话题相关性打分与观点收敛判定。

## User Stories

1. As a 作者, I want 开启群聊讨论时选择参与的角色、讨论主题与注入的静态设定，so that 讨论的成员、议题与上下文由我掌控。
2. As a 作者, I want 看到每个群成员的头像、名字与角色定位标签，so that 我一眼知道谁在发言、各角色负责什么。
3. As a 作者, I want 任一时刻只有一位成员发言、其余成员等待，so that 讨论有序、不互相打断。
4. As a 作者, I want 看到当前哪位成员正在发言或思考，so that 我知道讨论为何等待，不会误以为卡住。
5. As a 作者, I want 随时作为群成员发送消息，so that 我能实时引导、补充、纠正讨论方向。
6. As a 作者, I want 用 @角色名 定向召唤某个 Agent 回应，so that 我能把话题精准抛给特定角色。
7. As a 作者, I want 点击群成员列表即可快速 @ 该角色，so that 我不必手打名字。
8. As a 作者, I want Agent 发言时能看到它回应的是哪条消息、哪位成员的观点，so that 讨论脉络清晰可溯。
9. As a 作者, I want 讨论接近共识时系统提前提示，so that 我有机会在结束前补充意见。
10. As a 作者, I want 手动终止讨论，so that 讨论跑偏或失控时我能随时叫停。
11. As a 作者, I want 达成共识后合成者产出结构化总结（核心共识 / 主要分歧 / 综合方案 / 行动建议），so that 讨论成果可直接落地。
12. As a 作者, I want 查看讨论完整记录，so that 我能复盘讨论过程。
13. As a 作者, I want 看到每位成员当前发言意愿与调度原因，so that 调度机制透明、可理解、可信任。
14. As a 作者, I want 长时间无人发言时有保底机制让下一位 Agent 开口，so that 讨论不会冷场卡死。
15. As a 作者, I want 刚发言过的角色进入冷却、意愿下降，so that 讨论不会被单一角色垄断。
16. As a 作者, I want Agent 发言意愿随话题相关性变化，so that 讨论聚焦当前议题而不跑题。
17. As a 作者, I want 群聊记录按书持久化，so that 刷新页面或重启应用后讨论仍可恢复。
18. As a 作者, I want 最终方案可应用到大纲 / 人物设定，so that 讨论成果真正写入创作。
19. As a 作者, I want Agent 讨论时能访问项目的世界观 / 人物 / 大纲等静态设定，so that 讨论基于真实设定而非空谈。
20. As a 作者, I want 群聊界面显示系统消息（成员加入、达成共识、讨论终止等），so that 状态变化清晰可见。
21. As a 作者, I want 我的发言被计入讨论历史与上下文，so that 后续 Agent 发言会承接我的意见。
22. As a 作者, I want 讨论中每个 Agent 的发言有完整内容可展开查看，so that 长回复不截断、可细读。
23. As a 作者, I want 讨论结束时保留合成者的最终方案并与过程记录分离展示，so that 结果与过程互不混淆。
24. As a 作者, I want 每个参与的 Agent 角色可复用既有角色蓝图并可自定义，so that 我能用已配置的角色加入群聊。

## Implementation Decisions

- **统一执行入口（唯一测试 seam）**：新增 `ChatSession` 编排器，面向路由与前端暴露 `start / sendUserMessage / stop / resume` 等操作，串起 发言权调度 → 上下文组装 → Agent 发言 → 意愿度更新 → 共识检测 →（达成）合成者总结 的完整生命周期。所有测试经它黑盒断言，不触碰内部模块。这是本 feature 的唯一 seam。
- **发言权调度（意愿度制）**：单一发言者模型——任一时刻至多一个 Agent 在生成；每个成员维护意愿度，系统在事件驱动 + 定时检查下选出最高分发言者。意愿度公式（来自已确认设计）：

```text
总意愿度 = 被@加成(+100)
         + 等待时间加成(+0~30)      // 越久没发言越高
         + 话题相关性(+0~50)        // Embedding 相似度
         + 角色特性加成(+0~20)      // 角色倾向，如冲突制造者更爱开口
         - 冷却惩罚(-20~-50)        // 刚发过言衰减，防垄断
         + 随机扰动(+0~10)          // 打破固定顺序
```

- **作者发言**：作者消息并行插入——不等待当前 Agent 生成完毕即可发出，调度器在下一个发言权窗口优先处理；解析 @（@角色名 / 点击成员 @），被 @ 者获得 +100 强意愿加成；作者发言计入讨论历史与上下文。
- **共识检测（综合检测）**：三路信号并判定——① 关键词信号（「我同意 / 一致 / 达成共识」等）② 观点收敛（最近 N 条发言经向量聚类，簇内相似度超过阈值）③ Agent 自评（每次发言附带 consensus 自评字段）；连续满足 → 触发合成者总结。
- **上下文管理（分层摘要）**：L1 最近 5 条完整消息 + L2 最近 20 条滚动摘要 + L3 全讨论要点；发言时按 角色共享上下文（`contextConfig.sharedContextKeys`）+ L1/L2/L3 + 作者历史指令 组装，控制 token 预算。
- **实时推送（SSE）**：复用 `agent.ts` 既有 SSE 模式与心跳，新增事件类型 `chat_message` / `speaker`（当前发言人）/ `agent_status`（思考、生成中）/ `consensus` / `system` / `done` / `error`。
- **Embedding 与向量库**：`@xenova/transformers` 本地加载 `paraphrase-multilingual-MiniLM-L12-v2`（384 维，离线推理）；Qdrant 以 Docker 部署，Node.js SDK `@qdrant/js-client-rest`；向量存储 讨论消息（话题相关性检索）与观点聚类；Embedding 服务与向量检索服务独立模块，供意愿度与共识检测消费。
- **消息存储（分层）**：讨论进行中常驻内存（实时快）；共识节点与最终方案落库；完整记录按书持久化（如 `memory/discussions/<sessionId>.json`），支持刷新 / 重启恢复；持久化层预留接口以便后续切换存储。
- **参与角色**：复用 `agent_roles.ts` 资产（提案者 / 合成者），讨论开始时按前端所选角色组建群；合成者在共识达成时执行总结。
- **与既有模块关系**：移除标准模式执行器 `discussion.ts` 与轮询路由 `discussions.ts`；保留 `agent_roles` 资产与 CRUD；SSE 模式对齐 `agent.ts`；前端 `DiscussionView.vue` 重构为群聊界面（保留应用阶段：保存文档 / 应用到大纲 / 应用到人设）。

## Testing Decisions

- **只测外部行为**：所有断言经 `ChatSession` 黑盒——给定（角色集合、主题、静态设定上下文、一段作者 / Agent 消息序列）→ 断言 发言人选择顺序、意愿度更新、@ 加成生效、冷却生效、作者消息插入时序、共识触发、合成者总结产出、SSE 事件顺序；不测内部模块。注入 fake LLM client（stub 接口）使断言确定性。
- **测试模块**：`ChatSession` 行为为主 seam；意愿度计算、共识检测、上下文组装、消息持久化 都经 seam 覆盖。
- **好测试的标准**：一个测试描述一个用户可见行为；能证明「@ 某人 → 该角色下一步发言」「连发多次 → 冷却使其让位」「话题跑偏 → 相关性拉回」「观点收敛 → 触发共识」「作者发言 → 立即插入且不计入调度队列」。
- **同类先例**：`backend/test/workflow_runner.test.ts`（黑盒 seam + fake LLM）、`agent_session_store.test.ts`（会话持久化）、`api.test.ts`（路由冒烟）。

## Out of Scope

- 跨书共享讨论、多位作者实时协作（首版单机单作者）。
- 语音 / 视频等富媒体讨论。
- 前端群聊界面视觉与交互打磨（另行前端 spec）。
- 讨论质量与共识判定阈值调优（仅实现接缝与机制）。
- 向量库 / Embedding 模型的运行时切换（首版固定 Qdrant + MiniLM，服务层预留接口）。
