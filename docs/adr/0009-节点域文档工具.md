# 0009：节点域文档工具与文档登记表

将 Agent 的通用文件读写工具（read_file / write_file）替换为「节点域文档工具」（save_document / read_document），
并用文档登记表（settings/documents.json）根治「Agent 生成文档后前端读不到」的问题。

## 决策

- **移除通用读写工具**：Agent 不再可用 read_file / write_file，杜绝模型随意读写任意路径。保留 web_search / ask_user / memory_search / read_current_state / list_states / switch_state。
- **新增节点域文档工具**：
  - `save_document(kind, content, title?, work_unit?, mode?)`：把内容写入该 kind 的标准文件，路径完全由程序决定，模型不能传任意路径；写入即登记。
  - `read_document(kind, work_unit?, max_chars?)`：读取该 kind 的标准文件内容。
  - `mode` 支持 write（默认，整体覆盖）与 append（Markdown 文档分段追加，支持长文档多轮写入）。
- **节点 × kind 权限矩阵**（可写 / 可读）：
  - ideation：写 core-elements、vision；读同左
  - worldview：写 worldview；读 core-elements、vision、worldview
  - characters：写 characters；读 core-elements、vision、worldview、characters
  - outline：写 outline；读 core-elements、vision、worldview、characters、outline
  - writing：写 chapter（需 work_unit）；读 outline、style、chapter（前一章/本章）
  - review：写 review；读 chapter（本章）、worldview、characters、outline、style
  - style：写 style、chapter（重写）；读 chapter（抽样）、style、characters
- **文档登记表 settings/documents.json**：kind → 文档列表（title / path / work_unit / modified）。save_document 写入即登记；前端按 `GET /projects/:id/documents?kind=` 查询，去掉硬编码文件名；登记表为空时全项目扫描标准路径回填兜底。
- **标准存储路径**（kind → 文件）：
  - core-elements → 核心要素.json（项目根，JSON）
  - vision → 故事愿景文档.md（项目根）
  - worldview → 世界观设定文档.md、characters → 人物设定文档.md、outline → 大纲设定文档.md、style → 风格规范文档.md
  - chapter → chapters/<no>.md（并入章节索引 chapters/index.json，work_unit 形如 ch3）
  - review → review/<no>-审阅报告.md（work_unit 形如 ch3）
- **正文节点自动串联**：save_document(kind=chapter) 由后端自动执行 章尾钩子 → L1 摘要 → 8 账本回写（chapter_writeback.ts），模型只产出正文；结构化静态设定（settings/*.json）与文档登记表并存，前者供前置检测与结构化展示，后者作为 Agent 产出的标准文档索引。

## 原因

用户反馈：Agent 生成世界观时写入《世界观设定文档.md》，而前端静态设定页读取 settings/worldview.json，两者不同步导致"暂无世界观设定"。此前依赖固定文件名，Agent 一旦换名前端就读不到。节点域文档工具 + 登记表把文件名收敛为程序内常量，前端按 kind 查询，从根上消除路径漂移。

## 后果

- 后端新增 backend/src/storage/document_registry.ts、backend/src/tools/document_tools.ts；ideation.ts 工具面移除 FileReadTool/FileWriteTool。
- prompts.ts / node_prompts.ts 中的 file_write / file_read 用法全部改为 save_document / read_document。
- 前端 WorldviewTab 等去掉硬编码文件名，改按 kind 查询文档；projects.ts 的 /documents 支持 kind 过滤。
- 旧数据兼容：登记表不存在或为空时自动扫描标准路径回填，旧文档仍可展示。
- 下一步：各流程节点系统提示词 / RAG 召回规则 / 上下文装配的细化设计（基于登记表读入标准文档）。
