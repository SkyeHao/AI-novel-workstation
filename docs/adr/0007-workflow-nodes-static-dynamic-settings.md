# 0007：流程节点 × 静态/动态设定模型

将创作流程重构为 7 个流程节点（原「状态」正式改名），并为每个节点定义标准输出件；设定按「静态设定（故事宪法）」与「动态设定（世界真相层）」分治。

## 决策

- **术语定名（2026-08-18）**：原「状态 / 创作状态」统一改名「流程节点」。7 个默认流程节点：灵感捕捉 / 世界观构建 / 人物塑造 / 大纲生成 / 正文生成 / 质量审查 / 文风优化（可扩展、每书选启用）。
- **大纲生成 = 三级单节点**：总纲（起承转合/核心冲突/高潮结局）→ 分卷（各卷目标/阶段蓝图）→ 章纲（每章目标/情节点/伏笔安排），另附故事线 DAG；三级不拆成独立流程节点。
- **静态设定（故事宪法）**：低频变更，由对应流程节点生成，**仅生成节点可改**。清单：故事愿景文档 / 核心创意卡（灵感捕捉）、世界观信息（世界观构建）、人物设定 / 人物关系图（人物塑造）、大纲三级 + 故事线DAG（大纲生成）、风格规范（文风优化）。正文中的世界变化不直接改写静态设定。
- **动态设定（世界真相层）**：随故事推进而变，是 Agent 的全知真相层，由**正文生成**节点章末自动回写；界面只读（编辑需强提醒会影响上下文）。清单：人物动态状态（含状态时间线）/ 地点与势力状态 / 物品状态 / 事件流 / 故事时间线 / 伏笔台账 / 信息与视角状态 / 章节摘要链。
- **信息/视角状态独立**：动态账本「真相层 vs 展示层」独立常驻，记录世界实际事实与读者已被告知信息的差集；真相层仅供 Agent 全知视角，展示层约束正文披露边界。
- **伏笔管理改动态台账**：原流程节点 foreshadow 移出流程节点，改为动态设定中的伏笔台账（埋设/悬置/消费/超期提醒）；大纲生成埋设计划、正文生成推进消费。
- **文风优化 = 主动动作**：用户主动触发的低频动作，非自动环节——生成/校准风格规范，并按需对全书或选中章节做文风优化重写；触发后必须回写动态设定，避免正文与真相漂移。
- **双向修正规则**：用户手动改正文（修订/文风优化）必须触发动态层回写同步，否则真相与正文漂移。

## 原因

新版「系统设计.md」区分静态设定层（第一层）与动态叙事层（第二层），而旧模型中「状态」一词混用了三种语义（创作流程进度 / 故事世界真相 / 章节个体状态），造成概念混淆。用户确认：Agent 全知作者视角、状态由 Agent 自动更新、动态状态界面只读、文风优化用户主动触发、信息/视角状态独立。

## 后果

- 修订 ADR-0005 的默认 7 状态：移除「伏笔管理」流程节点位，新增「文风优化」，章纲节点内部三级化。
- 修订 CONTEXT.md 词汇：状态 → 流程节点，新增 静态设定 / 动态设定 / 信息与视角状态 / 大纲生成三级 / 文风优化。
- 数据模型影响：流程节点键集合更新（ideation/worldview/characters/outline/writing/review/style 候选）；动态设定为新的可浏览只读数据层，正文生成节点章末自动回写。
- 流程节点切换：模型上下文不携带前节点原始对话，靠「节点沉淀摘要（接力）+ 最近 N 条」重组，切回可恢复（见 design 1.6）。
- 下一步：进入各流程节点的 系统提示词 / RAG 召回规则 / 上下文装配 设计。
