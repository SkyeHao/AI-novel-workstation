### 1.2 通用上下文压缩规则（所有节点共用）

### 1.2 通用上下文压缩规则（所有节点共用，2026-08-19 增强）

压缩由四套机制协同：**模型感知窗口**、**阈值自动触发**、**摘要持久化 + 保留最近对话**、**Agent 主动压缩工具**。各节点块优先级差异见第 2~8 节，本节的机制对所有节点一致。

#### 1.2.1 模型感知的上下文窗口（按模型自动计算）
- 建立「模型 → 上下文窗口」映射表 `MODEL_CONTEXT_MAP`（按 provider/model 字符串匹配），自动查表得出该模型窗口；未命中时按序回退：显式配置（`MODEL_CONTEXT_WINDOW` 环境变量 / `LLMModelConfig` 覆盖）→ 映射表 → 默认 32768。
- 同一书不同任务（text/structure/check）可配不同模型，各自按自己的模型查窗口，互不影响。
- 预算仍为 `context_window − reserved_output_tokens`（默认保留 2048）；LLM 输出只吃保留余量，不占注入预算。

#### 1.2.2 阈值自动触发压缩（默认 80% 水位）
- 触发条件：每轮组装后估计「占用 / context_window ≥ `compression_ratio`」，默认 `0.80`（`CONTEXT_COMPRESSION_RATIO` 可配）。
- 压缩目标：把占用压到 `target_ratio`（默认 `0.60`）以下，为后续大量读取 / 输出留足余量。
- 触发时机：turn 前检测；已在阈值内则不压缩（避免频繁抖动）。

#### 1.2.3 历史摘要 + 保留最近对话 + 摘要持久化
- 压缩时保留**最近 N 条消息原样**（默认 `keep_recent`，如 12 条，可配），更早的历史才参与压块 / 裁块；函数调用与其结果成块配对保留/丢弃。
- 被压缩的历史由 LLM 生成**历史对话摘要**：作者核心需求与约束 / 已确认决策 / 已完成动作 / 待办 四类要点。
- 摘要**持久化**到会话文件（`memory/sessions/<session_id>.summary.json`，覆盖式保留最新），不是只临时注入——会话重开 / 断连恢复时先加载摘要再注入系统提示，保证压缩后上下文可续。
- 摘要与分层摘要 L1~L5 解耦：对话摘要是「与作者的协作过程」，分层摘要是「故事内容本身」，两者不混用。

#### 1.2.4 Agent 主动压缩工具 `compress_context`
- 暴露给 Agent 的工具 `compress_context`，参数可选：`reason`（压缩原因）、`keep_recent`（保留最近消息数，覆盖默认）。
- 建议触发时机（Agent 自行判断）：
  - 即将执行大量读取前（如读取整章正文、召回大量记忆、加载全部设定）。
  - 刚执行完复杂操作后（如长文档写入、正文生成、章末回写）。
  - 观察到上下文占用较高（长对话多轮后）。
- 工具语义：把较旧消息压成摘要并持久化、保留最近 N 条，返回压缩前后占用估计与摘要要点，Agent 据此决定后续动作。
- 与自动触发的分工：自动触发是**兜底**（硬水位），Agent 主动调用是**优化**（提前腾空间，避免撞到水位）。

#### 1.2.5 块分级与降级链（沿用）
- **硬块**（系统提示词、当前节点指令、用户本轮输入，不可裁）与**软块**（记忆注入、设定片段、分层摘要、产物模板、用户设置详情，可逐级降级）。
- **降级链**（超限 / 超阈值时按序执行，直到 fit，绝不静默丢硬块）：
  1. 裁块：按各节点软块优先级从低到高整块移除。
  2. 压块：对最长软块就地压缩成要点（保留事实、丢修饰）。
  3. 摘要兜底：细粒度摘要替换为上一级粗摘要（L2→L1、L3→L2…，联动分层摘要 L1~L5）。
  4. 熔断：仍超限 → 拒绝生成并明确提示（不偷偷降质）。
- **审计**：每次压缩记录「触发方式（自动 / Agent 主动）/ 哪块被裁 / 压 / 降级 / 压缩前后占用」，存日志，供调参。

### 1.5 动态设定章末回写协议（正文生成专属步骤）

正文生成节点输出章节正文后，必须执行一次「章末回写」（不可跳过）：
1. 提炼本段事件，更新**事件流**（新事件 + 因果关联）。
2. 逐角色更新**人物动态状态**（数值/心境/关系/目标），记入状态时间线。
3. 更新涉及**地点/势力状态**与**物品状态**（归属/完好/下落）。
4. 更新**故事时间线**（发生日、角色位置）。
5. 更新**伏笔台账**：消费已兑现的伏笔、登记新埋伏笔。
6. 更新**信息/视角状态**：把「本段向读者透露的事实」记入展示层；若作者采用全知或内视角，登记真相层实际发生但读者未知的事实。
7. 生成**章节摘要**（50~100 字）与**章尾钩子**，写入摘要链并触发分层摘要 L1 更新。
8. 更新 C 层章节状态：待生成 → 已生成 →（质量审查后）已审 →（定稿）定稿。
- **双向修正**：用户手动改正文（修订 / 文风优化重写）必须重新执行本协议，否则真相与正文漂移。

#### 1.5.1 章尾钩子（衔接机制）
- **定义**：本章结尾留下的一句话钩子，用于勾住读者、并作为**下一章的开头输入**保证衔接。
- **类型**：悬念型（抛出未解问题）/ 反转型（给出意外信息）/ 期待型（承诺某事或某场面将要发生）。
- **落盘**：随章节摘要一起持久化到章节记录 `hook` 字段（属 C 层章节元数据，并入章节摘要链）。
- **衔接规则**：
  - 本章开头必须承接上一章章尾钩子（开场呼应 / 解决 / 转折），禁止跳戏、禁止无视上一章结尾的悬念。
  - 本章结尾生成新钩子（默认 1 个，最多 2 个），预告下一章；卷末 / 全书终章按作者意图豁免。
  - 钩子必须与章纲功能匹配（如章纲明确「本章收尾」则不设钩子），且不得透露展示层未允许的事实（真相层信息差仍受 1.5 第 6 条约束）。

### 1.6 流程节点切换与上下文构建（C 方案，2026-08-19 已确认）

**场景**：同一个 Agent 会话内，用户从 A 节点切到 B 节点，对话线不中断、聊天记录保留。

#### 分层
- **会话记录（UI 层）**：切换节点不删除历史，按会话持久化；切回原节点仍可见原对话。
- **模型上下文（注入层）**：切换时重组。

#### 切换注入规则（A → B：携带最近几条 + 先前对话摘要）
B 节点的模型上下文按序注入：
1. 流程节点标签 + B 节点系统提示词（①）
2. **成果注入**：B 节点需要的静态设定 / 动态设定 / 分层摘要（按 B 节点的 ②③ 规则）
3. **先前对话摘要**：A（更早）对话压缩成的摘要——承载跨节点的作者决策与约束
4. **最近 N 条消息**（默认 12）：维持对话连续性
5. 记忆召回（按 B 节点 ② 规则）

#### 摘要怎么来
- 切换节点时（或上下文超阈值时，见 ADR-0008）把当前对话历史压成摘要（作者核心需求 / 已确认决策 / 已完成动作 / 待办），随会话持久化。
- A 原始对话轮次**不注入 B**，只以摘要 + 最近 N 条形式进入。
- 切回 A 同理：恢复 A 的摘要 + 最近 N 条 + A 需要的成果。

#### 预算
- 摘要 + 最近 N 条合计占注入预算小头（摘要 ≤ 注入预算 15%），超限走降级链。

## 2. 灵感捕捉

**定位**：把一个 IDEA 孵化成可动笔的「核心创意卡 + 故事愿景文档」。零书内记忆节点。
**标准输出件**：核心创意卡（静态，`核心要素.json`）、故事愿景文档（静态，`故事愿景文档.md`）。

### ① 系统提示词草案
- 角色：资深网文主编 + 创意策划人。目标是把 IDEA 打磨成可动笔的网文项目，不是写正文。
- 铁律：
  - 一次只确认一个要素（`ask_user` 结构化选项推进），不要一次性抛 5 个问题。
  - 四要素确认顺序：主线 → 风格 → 世界观钩子 → 金手指/爽点（可按作者意图调整）。
  - 每个要素确认后立即回写核心创意卡；未确认的决策绝不擅自假设。
  - 身份归属（金手指、爽点等）记录来源与作者拍板结论。
- 产出：四要素齐备 → 问作者是否生成愿景文档 → 先写 `核心要素.json` 再据其展开 `故事愿景文档.md`（长内容分段写入 ≤2000 字符/轮）。
- 结束条件：作者明确满意或要求结束时，末行输出 `<<DONE>>`。

### ② RAG 召回规则（召回量最低）

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 全程 | 核心创意卡已确认部分 | `核心要素.json` | 全量（短） |
| 生成愿景时 | 用户偏好（文风/题材倾向） | 用户设置 | 关键字段 |
| 不做 | 正典事实 / 章节摘要 / 动态状态 | ——（不存在） | 0 |

### ③ 上下文装配顺序
1. 流程节点标签（当前「灵感捕捉」，下一步世界观构建）
2. 灵感捕捉系统提示词（①）
3. 核心创意卡进度（已确认要素 → 待确认要素清单）
4. 用户设置（偏好、模型选择、写作目标）
5. 产物模板 guide（愿景文档结构 / 核心要素结构）
6. 记忆/动态设定：**不注入**（避免干扰）

### ④ 上下文压缩规则

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 | 硬块 | 1 | 不可裁 |
| 流程节点标签 | 硬块 | 1 | 不可裁 |
| 核心创意卡进度 | 硬块 | 1 | 不可裁（短） |
| 产物模板 guide | 软块 | 2 | 压成字段名列表 → 再裁 |
| 用户设置详情 | 软块 | 3 | 先裁，只留关键偏好关键词 |

**兜底**：L1~L5 分层摘要为空、书内无记忆，降级链只走到「熔断」即可；无摘要兜底场景。

## 3. 世界观构建

**定位**：基于核心创意卡，把世界搭建为结构化「宪法」。**仅本节点可改**世界观信息。
**标准输出件**：世界观信息（静态设定）——地理、历史、力量体系规则、社会文化、硬约束。

### ① 系统提示词草案
- 角色：世界观架构师。目标是把世界规则写成可被后续节点逐条引用的结构化设定。
- 职责：
  - 一次聚焦一个领域：先地理与时代背景 → 力量体系（规则/等级/限制/代价）→ 社会文化 → 硬约束。
  - 输出严格遵循世界观 JSON 模板（sections: era/rules/geography/factions/history），每轮一个合法 JSON。
  - 每条设定必须「可验证、可被正典事实引用」，不写装饰性空话。
  - 与核心创意卡冲突时，先 `ask_user` 拍板，不得自行取舍。
- 铁律：世界观是**宪法**，后续正文只可引用、不可违背；若剧情需要世界变化，记入动态「地点/势力状态」而非改写本设定。

### ② RAG 召回规则

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 全程 | 核心创意卡（题材/时代/钩子） | `核心要素.json` | 全量 |
| 续写时 | 已生成世界观（避免重复/冲突） | 世界观设定 | 全量 |
| 生成前 | 用户偏好（题材倾向） | 用户设置 | 关键字段 |

### ③ 上下文装配顺序
1. 流程节点标签
2. 世界观构建系统提示词（①）
3. 核心创意卡（硬）
4. 已生成的世界观部分（续写时，软）
5. 世界观 JSON 模板（软）
6. 用户设置（软）

### ④ 上下文压缩规则

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 / 节点标签 | 硬块 | 1 | 不可裁 |
| 核心创意卡 | 硬块 | 2 | 不可裁 |
| 已生成世界观 | 软块 | 3 | 压成「领域 → 一句话要点」→ 再裁 |
| 世界观模板 | 软块 | 4 | 压成字段名列表 |
| 用户设置 | 软块 | 5 | 先裁，留关键偏好 |

**兜底**：无书内记忆，摘要兜底不适用；走熔断。

## 4. 人物塑造

**定位**：生成人物设定（静态）与初始人物动态状态快照（动态基线）。**仅本节点可改**人物设定。
**标准输出件**：人物设定 + 人物关系图（静态）、初始动态状态快照（动态，正文节点起接管更新）。

### ① 系统提示词草案
- 角色：人物设定师。目标是让人物有「不会 OOC 的行为红线」与「可追踪的状态基线」。
- 职责：
  - 每人生成：基础档案、五维性格DNA、行为红线、能力基线（初始数值）、语言指纹、POV 规则。
  - 人物关系图记录静态基线关系（亲属/朋友/敌对/同盟）；关系后续演变归动态层。
  - 输出遵循人物 JSON 模板（characters[]，含 id/name/role/personality/goal/flaw/golden_finger/relations）。
  - 每个角色必须与世界观硬约束兼容（如禁魔世界不得默认会魔法）。
- 铁律：金手指必须有限制与代价；人物初始动态快照（能力数值/装备/物品）随人物生成一次落盘，正文节点章末接管更新。

### ② RAG 召回规则

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 全程 | 核心创意卡（金手指/爽点） | `核心要素.json` | 全量 |
| 生成角色时 | 世界观摘要（力量体系/硬约束） | 世界观设定 | 摘要级 |
| 续写时 | 已有人物卡（避免重名/重复职能） | 人物设定 | 全量 |
| 生成后 | 初始动态快照确认 | 动态设定（新） | 全量 |

### ③ 上下文装配顺序
1. 流程节点标签
2. 人物塑造系统提示词（①）
3. 核心创意卡（硬）
4. 世界观摘要（软，压缩成要点）
5. 已有人物卡（软，续写时注入）
6. 人物 JSON 模板（软）

### ④ 上下文压缩规则

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 / 节点标签 | 硬块 | 1 | 不可裁 |
| 核心创意卡 | 硬块 | 2 | 不可裁 |
| 世界观摘要 | 软块 | 3 | 压成「硬约束 + 力量体系」两行 |
| 已有人物卡 | 软块 | 4 | 压成「id + 名字 + 一句话职能」 |
| 人物模板 | 软块 | 5 | 压成字段名列表 |

**兜底**：无书内记忆，摘要兜底不适用；走熔断。

## 5. 大纲生成

**定位**：把故事愿景拆成可执行的三级大纲 + 故事线 DAG + 伏笔埋设计划。**仅本节点可改**大纲。
**标准输出件**：大纲三级（总纲 → 分卷 → 章纲）、故事线 DAG（静态）；伏笔台账「埋设计划」写入动态层。

### ① 系统提示词草案
- 角色：总编 + 结构设计师。目标是把愿景落到「每章都能执行」的三级结构。
- 职责：
  - 先总纲（起承转合/核心冲突/高潮/结局）→ 再分卷（各卷目标/阶段蓝图/目标字数）→ 最后章纲（每章事件/功能：铺垫|冲突|爽点|过渡|钩子/cast/伏笔埋设与回收）。
  - 维护故事线 DAG：主线与支线的分支、汇合点，确保支线可汇入主线。
  - 埋设伏笔时必须登记到伏笔台账（编号、埋设章、预期回收章、超期阈值默认 10 章）。
  - 章纲必须与世界观硬约束、人物行为红线兼容。
- 铁律：伏笔埋设/回收都登记台账；章纲不得制造「读者已知信息」与真相层冲突（信息差由正文节点按展示层披露）。

### ② RAG 召回规则

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 生成总纲/分卷 | 核心创意卡 + 愿景摘要 | `核心要素.json` / 愿景文档 | 全量 |
| 生成章纲时 | 世界观摘要 + cast 人物摘要 | 世界观 / 人物设定 | 摘要级 |
| 生成章纲时 | 活跃伏笔（避免重复埋设/安排回收时机） | 伏笔台账 | 活跃+超期 |
| 续写时 | 现有大纲（分卷/章纲，避免矛盾） | 大纲设定 | 后续部分 |

### ③ 上下文装配顺序
1. 流程节点标签
2. 大纲生成系统提示词（①）
3. 核心创意卡 + 愿景摘要（硬）
4. 世界观摘要 + 人物摘要（软）
5. 现有大纲（续写时，软）
6. 活跃伏笔台账（软，只列活跃 + 超期）
7. 大纲 JSON 模板（软）

### ④ 上下文压缩规则

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 / 节点标签 | 硬块 | 1 | 不可裁 |
| 核心创意卡 + 愿景摘要 | 硬块 | 2 | 不可裁 |
| 世界观/人物摘要 | 软块 | 3 | 压成「硬约束 + 关键人物」两行 |
| 现有大纲 | 软块 | 4 | 压成「卷 → 目标」要点，再裁后段 |
| 活跃伏笔台账 | 软块 | 5 | 只留「编号 + 一句话 + 超期标记」 |
| 大纲模板 | 软块 | 6 | 压成字段名列表 |

**兜底**：无书内正文摘要，摘要兜底不适用；走熔断。

## 6. 正文生成

**定位**：全书最复杂的节点。既输出章节正文（展示层），又章末自动回写全部动态设定（真相层）。
**标准输出件**：章节正文（展示层）+ 章尾钩子（衔接机制，见 1.5.1）+ 8 个动态账本更新（章末回写协议，见 1.5）+ 章节摘要。

### ① 系统提示词草案
- 角色：网文写手。目标：基于当前章纲与最新世界真相，写出推进剧情、符合风格、只披露到展示层允许程度的正文。
- 职责：
  - 本章目标来自对应**章纲**（事件 / 功能 / 爽点 / 钩子），不得偏离。
  - 注入的**人物动态状态 / 地点势力状态 / 物品状态**必须严格遵守，不得写与状态矛盾的内容（如公司已倒闭仍写其经营）。
  - 遵守**信息/视角状态**：只把展示层已允许的事实写进正文；真相层仅供 Agent 全知，读者不该知道的不能透露。
  - 遵守**POV 规则**与**人物语言指纹 / 行为红线**，防 OOC。
  - 遵守**风格规范**（叙事口吻、节奏、反AI味），风格未生成前用用户默认偏好。
  - 主动调用伏笔台账核对：本章应兑现的伏笔必须兑现，应埋的伏笔登记埋设。
  - **开头承接上一章章尾钩子**（开场呼应 / 解决 / 转折），结尾生成新钩子（悬念 / 反转 / 期待，一句话），落盘到章节记录 `hook` 字段。
  - 长章分轮输出（每轮 ≤ 输出上限），写完后执行**章末回写协议**（见 1.5）。
- 铁律：真相层与展示层的差集是悬疑/反差的核心资产，正文生成是唯一「披露」入口。

### ② RAG 召回规则（召回最重）

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 开写前 | 当前章纲（目标/功能/cast/伏笔） | 大纲设定 | 1 章 |
| 开写前 | **上一章章尾钩子**（衔接本章开头） | 章节记录 hook | 1 条 |
| 开写前 | cast 角色动态状态 | 动态设定 | cast 数 |
| 开写前 | 涉及地点/物品状态 | 动态设定 | 相关项 |
| 开写前 | 近期事件流 + 故事时间线（防矛盾） | 动态设定 | 近 N 条 |
| 开写前 | 活跃伏笔（本章要兑现/推进的） | 伏笔台账 | 活跃 |
| 开写前 | 分层摘要 L1/L2（前文骨架） | 摘要链 | L1 近几章 + L2 |
| 开写前 | 风格规范 + 用户偏好 | 风格设定 / 用户设置 | 全量（短） |
| 开写前 | 世界观/人物摘要（远程兜底） | 静态设定 | 摘要级 |

### ③ 上下文装配顺序
1. 流程节点标签
2. 正文生成系统提示词（①）
3. 当前章纲（硬）
4. **上一章章尾钩子**（一句话，衔接）（软，短）
5. 动态设定注入块（cast 角色 / 地点物品 / 事件流 / 时间线 / 活跃伏笔 / 信息视角展示层）（软）
6. 分层摘要 L1（近几章）+ L2（软）
7. 风格规范 + 用户偏好（软）
8. 世界观/人物摘要（软，兜底）
9. 记忆召回（keyword，`injectAll` 活跃伏笔 + 正典事实兜底）（软）

### ④ 上下文压缩规则（注入量最大，压缩最常触发）

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 / 节点标签 | 硬块 | 1 | 不可裁 |
| 当前章纲 | 硬块 | 2 | 不可裁 |
| 上一章章尾钩子 | 软块（短） | 2 | 一句话，随硬块保留（几乎不裁） |
| 动态设定（角色/地点/物品） | 软块 | 3 | 压成「名字 + 数值卡」一行/人 |
| 活跃伏笔台账 | 软块 | 4 | 只留「编号 + 一句话」 |
| 分层摘要 | 软块 | 5 | 先 L1→L2 降级，再裁更早章节 |
| 风格规范 | 软块 | 6 | 压成「口吻 + 节奏 + 反AI味」三行 |
| 事件流 / 时间线 | 软块 | 7 | 压成近 3 条要点 |
| 世界观/人物摘要 | 软块 | 8 | 先裁（正典事实兜底） |

**降级链优先级**：8 → 7 → 6 → 5 → 4 → 3 逐级压/裁，硬块（1、2）与上一章钩子（短块）永不动。仍超限走「摘要兜底」（把 L1 降 L2、L2 降 L3）→ 最后熔断。
**特别注意**：动态状态压块时只能压缩叙述、**不得删改数值事实**；压过的状态在章末回写时仍以模型输出为准，压缩只影响本轮输入视角。

## 7. 质量审查

**定位**：对已生成章节做多维质检，输出质检报告并决定「通过 / 打回修订」。质检结果驱动 C 层章节状态流转。
**标准输出件**：质检报告（张力评分 / 一致性 / 文风漂移 / 陈词滥调 / 修订建议）；通过后章节状态 → 已审。

### ① 系统提示词草案
- 角色：资深编辑 + 逻辑检查员 + 读者代表。目标：把「能发出去」与「有问题要改」分清楚，报告可执行。
- 审查维度：
  - 角色一致性：言行是否符合性格 DNA / 行为红线（OOC 告警）。
  - 世界观一致性：是否违背硬约束（禁魔区施法等）。
  - 时间线一致性：事件顺序、角色位置是否符合时间线与事件流。
  - 爽点节奏：与章纲功能是否匹配（该爽的章有没有爽到）。
  - 信息一致性：正文披露是否超出展示层允许范围。
  - AI 味：陈词滥调 / 套路句扫描。
- 输出：结构化质检报告（维度 / 结论 / 证据位置 / 修订建议）；不合格 → 触发修订（可迭代，连续 3 次不合格走熔断，暂停并请作者介入）。

### ② RAG 召回规则

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 全程 | 被审章节正文 | 正文章节 | 1 章 |
| 审查角色/世界维度 | 涉及角色设定 + 世界观硬约束 | 静态设定 | 相关项 |
| 审查时间线 | 事件流 + 时间线 | 动态设定 | 近 N 条 |
| 审查信息差 | 信息/视角状态（展示层） | 动态设定 | 全量 |
| 审查文风 | 风格基线 | 风格设定 | 全量 |

### ③ 上下文装配顺序
1. 流程节点标签
2. 质量审查系统提示词（①）
3. 章节正文（硬）
4. 相关静态设定（角色/世界观对照，软）
5. 事件流 + 时间线（软）
6. 信息/视角状态·展示层（软）
7. 风格基线（软）

### ④ 上下文压缩规则

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 / 节点标签 | 硬块 | 1 | 不可裁 |
| 章节正文 | 软块 | 2 | 压成「逐段要点」→ 再裁最早段落 |
| 相关静态设定 | 软块 | 3 | 压成「角色红线 + 硬约束」两行 |
| 事件流/时间线 | 软块 | 4 | 压成近 3 条要点 |
| 信息视角展示层 | 软块 | 5 | 只留「已披露事实清单」 |
| 风格基线 | 软块 | 6 | 压成三行要点 |

**兜底**：正文摘要可作为被审章节的远程对照（L1 摘要），但**审查必须基于全文本**；若超限，先压其它块，正文压块为最后手段。

## 8. 文风优化（主动动作）

**定位**：用户主动触发的低频动作，非自动环节。生成/校准风格规范，并按需对全书或选中章节做文风优化重写。触发后必须执行章末回写协议。
**标准输出件**：风格规范（静态设定）——风格引擎、写作偏好、命名规范、反AI味规则；可选：重写后的章节正文。

### ① 系统提示词草案
- 角色：文风风格师。目标：把「读起来像什么」提炼成可执行、可检测的风格规范。
- 职责：
  - 从用户偏好 + 代表性章节提取风格特征（叙事口吻、对话/叙述比例、句式节奏、词汇频次）。
  - 输出风格规范（style 字段：整体描述一段话）+ 命名规范（人名/地名/招式/组织名风格统一）。
  - 绑定反 AI 味规则库（陈词滥调 / 套路句黑名单）。
- 重写模式：用户指定范围（全书 / 选中章节）→ 重写后**必须重新执行章末回写协议**（事件/状态/伏笔/信息视角/摘要全量对齐），否则真相与正文漂移。
- 铁律：文风优化只改「表达」，不得改变事实与事件顺序；如有冲突先 `ask_user`。

### ② RAG 召回规则

| 触发时机 | 召回内容 | 来源 | 上限 |
|---|---|---|---|
| 提炼风格时 | 代表性章节（首章 + 抽样 N 章） | 正文章节 | 抽样 |
| 生成命名规范 | 人名/地名/招式现状 | 静态设定 | 全量 |
| 重写时 | 被重写章节 + 相关动态状态 | 正文 / 动态设定 | 相关项 |

### ③ 上下文装配顺序
1. 流程节点标签
2. 文风优化系统提示词（①）
3. 用户偏好 + 现状风格规范（软）
4. 代表性抽样章节（软）
5. 命名表（人名/地名，软）
6. 重写时追加：目标章节 + 相关动态状态（软）

### ④ 上下文压缩规则

| 块 | 级别 | 优先级 | 超限处理 |
|---|---|---|---|
| 系统提示词 / 节点标签 | 硬块 | 1 | 不可裁 |
| 用户偏好 + 现状风格规范 | 硬块 | 2 | 不可裁（短） |
| 代表性抽样章节 | 软块 | 3 | 压成「风格特征」要点，再裁旧样本 |
| 命名表 | 软块 | 4 | 压成「类型 → 代表词」 |
| 目标章节 + 动态状态（重写时） | 软块 | 5 | 动态状态压成数值卡 |

**兜底**：无书内正典摘要专门用于文风；若抽样章节超限，优先压样本而非风格规范。

## 9. 跨节点差异一览表

| 节点 | 输入依赖（RAG 主线） | 输出件 | 压缩触发频率 | 摘要兜底 |
|---|---|---|---|---|
| 灵感捕捉 | 无（零记忆） | 核心创意卡 + 愿景文档 | 几乎不触发 | 无 |
| 世界观构建 | 核心创意卡 | 世界观信息 | 低 | 无 |
| 人物塑造 | 创意卡 + 世界观摘要 | 人物设定 + 初始动态快照 | 低 | 无 |
| 大纲生成 | 创意卡 + 世界观/人物摘要 + 活跃伏笔 | 大纲三级 + DAG + 伏笔计划 | 中 | 无 |
| 正文生成 | 章纲 + 动态状态 + 摘要 + 伏笔 + 风格 | 正文 + 8 账本回写 | **最高** | L1→L2→L3 |
| 质量审查 | 正文 + 相关设定 + 事件流 + 展示层 | 质检报告 | 中 | 正文摘要兜底（最后手段） |
| 文风优化 | 抽样章节 + 命名表 + 偏好 | 风格规范（+重写正文） | 低 | 无 |

### 9.1 关键铁律汇总
1. 静态设定**仅生成节点可改**；世界变化记入动态层。
2. 动态设定由**正文生成章末自动回写**，界面只读；编辑需强提醒。
3. **信息/视角状态独立**：真相层 vs 展示层；正文只披露展示层允许的事实。
4. **伏笔台账**：大纲埋设、正文推进/消费；超期（默认 10 章）提醒。
5. **文风优化 = 主动动作**；重写后必须回写动态层。
6. 压缩永远不动硬块；超限走降级链，最后熔断提示，不偷偷降质。
