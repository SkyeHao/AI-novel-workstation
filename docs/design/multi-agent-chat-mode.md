# 多 Agent 群聊模式（ChatSession）详细设计（v1.0 · 2026-08-24）

> 本文是 ADR-0010 的可执行设计稿，描述「群聊模式」：多个 Agent 角色与作者在同一实时讨论房间内自由发言，达成共识后由合成者产出最终方案。
> 前置概念（Agent 角色蓝图 / 静态设定 / 动态设定 / 单书记忆）见 `CONTEXT.md`；决策记录见 `docs/adr/0010-multi-agent-chat-mode.md`；测试接缝与验收口径见 `.scratch/multi-agent-chat-mode/spec.md`。

---

## 1. 设计总览

### 1.1 目标

把「标准模式」的并行产出 + 汇总升级为真正的多 Agent 讨论：

- 任一时刻至多一个成员发言，其余等待，讨论有序、不互相打断。
- 不同角色设定真正体现差异：冲突制造者交锋、情感锚点兜底、意外推手破局、世界守护者守设定。
- 作者作为群成员实时参与、引导、打断，不再被隔离在流程外。
- 讨论过程全程可见、可复盘；达成共识自动收尾，作者可随时手动终止。
- 上下文分层管理，长讨论不膨胀、不失真、可控 token 预算。

### 1.2 与标准模式差异

| 维度 | 标准模式（移除） | 群聊模式（新增） |
|---|---|---|
| 交互 | 管线式：提案→审查→合成→审查→应用 | 微信群聊式实时讨论房间 |
| 发言 | 各 Agent 独立生成后汇总 | 意愿度调度，单一发言者轮流发言 |
| 作者 | 只在审查点追加指令 | 群成员，实时插入 + @ 定向召唤 |
| 结束 | 固定阶段数 | 共识检测自动结束 / 手动终止 |
| 过程可见性 | 讨论过程不可见 | SSE 实时推送消息、发言人、状态、共识进度 |
| 上下文 | 简单全量拼贴 | L1/L2/L3 分层上下文 |
| 后端 | 轮询异步任务 | 常驻会话 + 事件驱动调度 |

### 1.3 系统组成

| 模块 | 职责 |
|---|---|
| ChatSession 编排器 | 唯一 seam，串起 调度→上下文→发言→意愿度→共识→合成 全生命周期 |
| SpeakerScheduler | 意愿度计算与发言者选择、冷却、@ 加成、定时兜底 |
| ConsensusDetector | 三路信号（关键词 / 向量收敛 / 自评）判定 |
| ContextAssembler | L1/L2/L3 分层组装、token 预算 |
| SseNotifier | SSE 事件推送（对齐 agent.ts 模式） |
| EmbeddingService | 本地多语言 Embedding（384 维） |
| VectorStore | Qdrant 向量检索（相关性、聚类） |
| ChatStore | 内存 + 落库 + 文件持久化 |

## 2. 群聊生命周期状态机

```
idle ──start──▶ running ──达成共识──▶ synthesizing ──总结完成──▶ completed
  ▲                  │
  └─────── terminated ◀──────── 作者手动终止 / 异常 ─────────┘
```

| 状态 | 含义 | 进入 / 退出 |
|---|---|---|
| idle | 会话已创建，尚未开始 | POST /chat-sessions/start → running |
| running | 群聊进行中，调度器分发发言权 | 达成共识 → synthesizing；作者终止 → terminated |
| synthesizing | 共识达成，合成者产出总结 | 总结完成 → completed |
| completed | 会话结束，可查看 / 应用方案 | — |
| terminated | 作者手动终止 | — |

## 3. 发言权调度（意愿度制）

### 3.1 原则

单一发言者模型：任一时刻至多一个 Agent 在生成，其余等待；作者消息并行插入（不阻塞当前生成），在下一个发言权窗口优先处理。

### 3.2 意愿度公式

```
总意愿度 = 被@加成(+100)
         + 等待时间加成(+0~30)      // 越久没发言越高
         + 话题相关性(+0~50)        // Embedding 相似度（最近消息 vs 角色相关设定）
         + 角色特性加成(+0~20)      // 冲突制造者等角色倾向
         - 冷却惩罚(-20~-50)        // 刚发过言衰减，防垄断
         + 随机扰动(+0~10)          // 打破固定顺序
```

### 3.3 调度时机

- 事件驱动：作者消息插入、某 Agent 发言完成后立即触发一轮重算。
- 定时兜底：距上一条消息超过 `IDLE_TIMEOUT`（默认 30s）且无人发言 → 强制选最高分者发言，防冷场。
- 选择：当前候选（未在冷却的 Agent）中分数最高者获得发言权；同分随机。

### 3.4 透明性

每次发言前推送 `speaker` 事件，附带得分明细（各分项 + 总分 + 一句话原因），前端展示在消息上方，让调度可理解、可信任。

## 4. 作者参与

- 作者是群成员，可随时发送消息，实时并行插入，不阻塞当前 Agent 生成。
- 作者发言计入 L1/L2/L3 上下文与讨论历史，后续 Agent 发言会承接作者意见。
- @ 语法：`@角色名` 定向召唤，被 @ 者获得 +100 强意愿加成，下一个发言权窗口大概率由被 @ 者发言；支持点击群成员列表快速 @。

发言后的下一个发言权窗口：若有 @ → 被 @ 者发言；否则按意愿度正常调度。

## 5. 共识检测（综合检测）

### 5.1 三路信号

| 信号 | 检测方式 | 说明 |
|---|---|---|
| ① 关键词信号 | 正则匹配「我同意 / 一致 / 达成共识 / 认同 / 没有异议」等 | 显式表态 |
| ② 观点收敛 | 最近 8 条发言向量聚类，簇内平均相似度 ≥ 0.70 | 语义收敛 |
| ③ Agent 自评 | 每次发言附带 consensus 自评字段（同意 / 保留 / 异议） | 角色自述 |

### 5.2 判定

- 连续 2 轮加权评分超过阈值即触发合成：关键词 0.6 / 收敛 0.75 / 自评 0.7（默认，可配）。
- 触发前推送 `consensus` 预警事件，作者有机会在结束前补充意见。
- 达成后进入 synthesizing，合成者按模板产出：核心共识 / 主要分歧 / 综合方案 / 行动建议。

## 6. 上下文管理（分层摘要）

| 层 | 内容 | 用途 |
|---|---|---|
| L1 | 最近 5 条完整消息 | 直接对话上下文 |
| L2 | 最近 20 条滚动摘要（增量压缩） | 近期脉络 |
| L3 | 全讨论要点（关键议题 / 已达成点 / 悬而未决点）+ 作者历史指令 | 全局视角 |

组装顺序（给每个发言 Agent）：系统提示（角色蓝图 + 角色特性）→ 静态设定（`contextConfig.sharedContextKeys`）→ L3 → L2 → L1 → 触发消息（被回应的消息原文）。按模型窗口控制预算，超限时降级 L2→L1 摘要粒度。

## 7. SSE 事件表

复用 `agent.ts` 的 SSE 模式与心跳。事件：

| 事件 | 载荷要点 | 触发 |
|---|---|---|
| chat_message | 成员、内容、回应引用 | 任意成员发言 |
| speaker | 当前发言人 + 得分明细 | 发言权分配 |
| agent_status | 思考中 / 生成中 | Agent 阶段切换 |
| consensus | 共识进度 / 预警 | 信号命中 |
| system | 成员加入 / 共识达成 / 终止 | 状态变化 |
| done | 会话结束 + 最终方案 | completed |
| error | 错误信息 | 异常 |

## 8. Embedding 与向量库

### 8.1 选型

| 项 | 选择 | 理由 |
|---|---|---|
| Embedding 模型 | paraphrase-multilingual-MiniLM-L12-v2（384 维） | 多语言（中英）、轻量、本地离线 |
| 运行库 | @xenova/transformers | 纯 JS、免 Python 环境 |
| 向量库 | Qdrant（Docker，默认 6333） | 部署简单、支持过滤与聚类 |
| 客户端 | @qdrant/js-client-rest | 官方 JS SDK |

### 8.2 用途

- 话题相关性打分（发言意愿度）：最近消息与角色相关设定嵌入后的相似度。
- 观点收敛判定：最近 N 条发言向量聚类，簇内相似度作为收敛信号。

### 8.3 模块边界

- `EmbeddingService`（模型加载、文本 embed）与 `VectorStore`（collection 管理、upsert / query / cluster）为独立服务。
- 连接失败降级：相关性退回关键词 + 随机，共识收敛退化为关键词 + 自评，不阻塞主流程。
- 与 ADR-0001 的关系：本 feature 是「讨论内的话题相关性与观点收敛」检索；单书记忆 RAG 仍维持 ADR-0001 的 keyword 轻量召回，互不推翻。

以上边界保证即使向量库不可用，讨论主流程仍可推进。

## 9. 消息存储（三层）

| 层 | 载体 | 用途 |
|---|---|---|
| 内存 | 会话对象 | 实时读写、调度 |
| 落库 | 共识节点 / 最终方案 | 持久化成果 |
| 文件 | memory/discussions/<sessionId>.json | 完整记录按书持久化，刷新 / 重启可恢复 |

持久化层预留接口，后续可切换存储。

## 10. 前端交互流程（7 步）

1. 资产页选择参与角色（复用 agent_roles 蓝图，可自定义）→ 填写主题 → 勾选注入的静态设定 → 开始讨论。
2. 进入群聊房间：成员列表（头像 / 名字 / 角色定位标签）+ 消息流 + 输入框。
3. 发言权分配 → 顶部 / 消息上方显示当前发言人及得分明细（speaker 事件）。
4. Agent 发言流式展示（chat_message），思考 / 生成中以「输入中」指示呈现（agent_status）。
5. 作者随时输入发言 / @ 角色（点击成员快速 @）。
6. 接近共识时系统预警（consensus）；达成后合成者产出总结，过程与结果分区展示（done）。
7. 应用阶段：保存文档 / 应用到大纲 / 应用到人设（复用标准模式的应用入口）。

## 11. API 契约草图

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/chat-sessions/start | 创建会话（角色集合 / 主题 / 静态设定上下文） |
| POST | /api/chat-sessions/:id/message | 作者发言（含 @ 解析） |
| POST | /api/chat-sessions/:id/stop | 手动终止 |
| GET | /api/chat-sessions/:id/stream | SSE 事件流 |
| GET | /api/chat-sessions/:id | 会话详情（含完整记录） |
| POST | /api/chat-sessions/:id/apply | 应用最终方案 |

## 12. 实施阶段

| 阶段 | 内容 | 产出 |
|---|---|---|
| Phase 1 | ChatSession 骨架 + 状态机 + SSE 基础事件 | 会话可启停、事件可推送 |
| Phase 2 | SpeakerScheduler（意愿度 / 冷却 / @ / 兜底） | 有序轮流发言 |
| Phase 3 | 作者消息并行插入 + 前端群聊界面 | 作者可实时参与 |
| Phase 4 | ConsensusDetector 三路信号 + 合成者总结 | 自动收尾 |
| Phase 5 | L1/L2/L3 上下文组装 | 长讨论可控 |
| Phase 6 | Embedding + Qdrant 集成 + 消息持久化 | 语义相关性与恢复 |
